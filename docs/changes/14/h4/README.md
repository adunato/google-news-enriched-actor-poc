## Frozen decision rule

The calibration can freeze a rule only when all of these hold:

- At least 76 of the 79 historical `confirmed_match` rows pass the combined rule (at least 96.2% sensitivity).
- No deliberately wrong title/source pairing passes any threshold considered by calibration.
- At least two distinct normalized title tokens occur in the candidate URL path. Tokens use NFKD, lowercase and Unicode letter/number runs of length 3 or more; URL query values are excluded. Numeric-only path components and generic `article`, `news`, `story` and `read` path words are excluded. A URL with fewer than two usable path tokens is indeterminate.
- The candidate's registrable domain, computed with the locked `tldts` Public Suffix List, matches the RSS source domain after `www` and IDNA normalization, or matches a specific alias in the hashed `aliases.json`.
- The Google News page marker ID equals the ID from the originating RSS URL and the RPC request is constructed from that marker.

Only a replayed candidate whose exact SHA-256 matches that row's `candidateUrlHash` in the frozen #18 hosted results inherits the historical positive label. Calibration selects the highest title-token-coverage threshold that still accepts at least 76 of all 79 historical positives; unstable hashes, missing candidates and other failed signals count as misses. It requires at least 76 hash-stable eligible positives, at least 76 **distinct valid candidate/title pairs** and zero negative accepts. A valid negative retains the positive candidate's source-domain match, pairs it with a different real title, and is deduplicated by candidate URL hash plus title normalized with NFKC, English lowercase, and collapsed non-letter/number separators. Rows and title choices are ordered deterministically. Same-publisher title swaps are preferred where available; when none is available, a deterministic different title from the known-positive corpus is used while preserving the candidate row's source domain. If the first title swap per row yields fewer than 76 distinct pairs, further title swaps are added in deterministic same-publisher-first order until the gate is met or the corpus is exhausted. Synthetic placeholder titles are prohibited. Calibration reports only known-positive control IDs, aggregate metrics and negative-control type counts, including the distinct-pair total. It does not print or persist per-row results from the unresolved set.

If these gates cannot be met, capture stops without writing a freeze and emits only the approved positive-control failure aggregates. The threshold must not be relaxed after looking at unresolved rows. H4a makes exactly one marker/RPC capture per manifest row; there is no repeat mode. A successful calibration writes the immutable freeze and encrypted candidate pack, then stops before `h4-apply.mjs`. Applying the freeze to the 21 unresolved rows remains a separate owner-approved iteration.

## Blindness and retained evidence

`h4-capture.mjs` performs the bounded marker/RPC replay (maximum five redirects, 10 second request timeout, 2 MiB response limit, concurrency four). Before any request, it takes an exclusive `h4-capture.lock`; a second process exits before making requests. It transiently holds the result for the full sample, computes calibration controls only from the historical 79 positives, and stages all evidence before atomically renaming one complete directory to `h4-evidence/`. A failed run publishes no partial evidence directory and cannot overwrite a previous run. A future calibration-gate failure may publish only the separate control-only report described above.

The only requested article page and redirect host is exactly `news.google.com` over HTTPS; the RPC request uses the fixed `https://news.google.com/_/DotsSplashUi/data/batchexecute` endpoint and does not follow redirects. Requests set no Cookie, Authorization, or Proxy-Authorization header and use no cookie jar. Candidate publisher URLs are never fetched. Candidate URLs and Google article identifiers exist transiently in memory and in the encrypted candidate pack only; they are absent from console output, calibration output and the application report. The request path relies on the host runtime's DNS/network routing; it does not pin DNS answers or establish a public-IP-only egress policy. That remains an operational network-boundary limitation.

The full candidate payload is encrypted in `h4-evidence/h4-candidates.sealed` using AES-256-GCM. Generate a fresh 32-byte key for the run, supply it as `H4_SEAL_KEY`, and retain it outside the repository until post-freeze application. No response bodies, cookies or credentials are retained.

`h4-evidence/h4-freeze.json` records the H4a iteration, frozen rule and threshold, control metrics, exact manifest and historical-label hashes, tool/check/config hashes, one-request operational limit and hash of the sealed payload. `h4-evidence/h4-calibration.json` has only known positive control IDs, realistic-control types and aggregate metrics. The encrypted payload contains all capture rows, but its contents remain inaccessible without the external key. Do not put the key in command history, Actor input, source control or logs.

`h4-apply.mjs` is a separate post-freeze command. It checks the freeze state, sealed-payload and calibration hashes, frozen manifest/label hashes, and frozen code/config hashes before decrypting. It retains only row IDs, status/reason, destination hashes and domain-level evidence in `h4-evidence/h4-application-results.json`; it does not retain candidate URLs or page/RPC bodies. It preserves the 79 prior direct confirmations and applies the frozen rule to the rest. `verified` requires all frozen binding, source-domain and title-path gates; `contradicted` is reserved for an affirmative article-ID mismatch; missing signals and other cases remain `unverifiable`. The report includes a computed verdict and marks H4 supported only when at least 16 rows are newly verified, at least 95/100 are supported, and there are no article-ID binding contradictions.

The success gate is at least 16 newly verified rows, giving at least 95/100 supported identities, with no contradiction of marker/RPC article-ID binding. Publisher-page accessibility is not used as identity evidence.

## Redirect diagnostic protocol

It checks the positive-label boundary, that unresolved-row fields are not read, destination fetching stops at the first disallowed hop, and dynamic URL/path/query values do not enter retained output. The fake fetch used by the tests is in-memory and makes no network requests.
